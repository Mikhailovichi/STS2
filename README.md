# STS2 Mods

**语言 / Language / 言語**: **简体中文** | [English](./README.en.md) | [日本語](./README.ja.md)

一个围绕《Slay the Spire 2》多人协作体验、战斗信息可视化和局内沟通效率构建的 mod 集合。

当前仓库包含三个独立但可以互相配合使用的模组：

- 🖋️ [CombatQuill](./CombatQuill): 在战斗与相关界面中进行战术标注和即时沟通
- 👀 [PartyObserver](./PartyObserver): 查看队友当前同步到本地的关键选择信息
- 📊 [DamageMeter](./DamageMeter): 统计并展示战斗输出、资源利用和复盘数据

这三个 mod 的方向并不是单纯做“功能补丁”，而是希望为联机环境补上一层更清晰的协作界面：

- `CombatQuill` 负责“说清楚现在该怎么打”
- `PartyObserver` 负责“看清楚队友正在做什么选择”
- `DamageMeter` 负责“复盘这场战斗到底发生了什么”

## ✨ 仓库定位

这个仓库更接近一个持续演进中的多人体验工具集，而不是单一功能的临时实验。  
目前三个模组都已经进入可运行、可迭代的阶段，但整体仍然处在早期公开版本：功能已经具备明确方向，界面和交互也已经能支撑实际使用，不过在联机同步深度、信息覆盖范围、细节打磨和长期数据能力上，后续还有不少扩展空间。

## 🖋️ CombatQuill

`CombatQuill` 的核心目标，是给联机战斗提供一个真正好用、又不会干扰原版操作流的标注层。

在多人局里，很多沟通本来都要靠语音或文字临时描述，比如“先打左边这个”“这张牌给这个怪”“这一回合我先挡，你负责收尾”。  
`CombatQuill` 想做的，就是把这些临场指挥从口头沟通转化成可视化的即时标记，让协作变得更直接。

### 功能描述

- 在战斗界面中提供可即时启用的绘制覆盖层，用于圈重点、画路线、标记目标和表达出牌顺序。
- 采用接近官方地图涂画工具的视觉语义，包括羽毛笔、橡皮和清空等工具，尽量让整体观感贴近原版风格。
- 默认将绘制操作放在相对安全的输入路径上，避免直接抢占原本的左键拖牌流程，减少误操作风险。
- 支持在战斗过程中快速开关，适合只在需要沟通的关键回合短暂启用，而不是强制长期占据屏幕。
- 已经具备基础颜色、笔触、橡皮、透明度和工具栏相关设置能力，可以根据个人习惯调整标注风格。
- 从协作体验上看，它并不是单纯“能画线”而已，更像是一个轻量级的战术白板：适合提前标记击杀顺序、集中火力对象、需要保留的敌人、或某个回合的资源分配重点。

### 版本展望

`CombatQuill` 后续最重要的方向，是从“本地可用的战斗标注”继续走向“真正适合联机协作的同步战术层”。

- 近阶段会优先补强联机同步能力，让标记不只是本地可见，而是能更稳定地被队友看到、理解和复用。
- 预计会继续完善标记归属、颜色语义和图层管理，让多人同时使用时不容易混淆“谁画的、画给谁看、哪一层还有效”。
- 会考虑补上跨战斗或短时持久化能力，让某些重要标记在切换界面后不会立刻消失，适合战斗后继续讨论刚才的处理。
- 控制器与自定义输入方案也是比较明确的后续方向。当前设计优先保障键鼠战斗安全性，后面会继续考虑更自然的手柄工作流。
- 更长期的版本里，`CombatQuill` 可能会从“绘图工具”继续演进成“战术表达工具”，比如加入更结构化的指示样式、重点标记、临时 ping、或更适合联机沟通的快捷语义。

## 👀 PartyObserver

`PartyObserver` 的目标，是把“我不知道队友现在在看什么、选什么、犹豫什么”这个联机常见问题，变成一个可以快速浏览的界面问题。

在多人模式下，队友的很多关键选择并不会天然清晰地展现在你眼前。  
你可能知道对方现在不在战斗里，但不知道他是在看奖励、看事件、还是已经做完选择；你也可能知道他在卡牌奖励界面，但并不清楚他具体在犹豫哪几张牌。  
`PartyObserver` 的作用，就是把这些“局内上下文”同步成一个简洁、稳定、低打扰的观察面板。

### 功能描述

- 在支持的界面中提供一个紧凑的队友观察面板，用来展示当前队友的同步状态。
- 已支持查看队友的卡牌奖励选择信息，以及事件房间中的选项内容。
- 当某些界面暂时没有更细粒度的数据时，仍然会回退显示队友当前所处的多人屏幕类型，让你至少知道他大致在处理什么内容。
- 观察面板采用轻量、可拖动的形式，不强行占据主界面，适合作为辅助信息层长期挂在联机过程中。
- 当前结构已经考虑到后续扩展，因此虽然现在的显示方式偏简洁，但底层并不是一次性写死的临时 UI，后面可以比较平滑地升级成更丰富的观察界面。

### 版本展望

`PartyObserver` 后续会继续沿着“把队友决策上下文更自然地带到你面前”这个方向推进，但它的目标并不是做一个完整的远程屏幕镜像，而是做一个更适合联机决策协作的状态与选择观察器。

- 近阶段最明确的扩展方向，是补全更多关键场景的同步观察能力，例如商店、篝火、升级、移除、变形、地图节点等。
- 后续版本会更重视“为什么队友在这个界面停留”和“他现在正在比较什么”，也就是从单纯展示屏幕类型，继续过渡到展示更有决策价值的上下文。
- UI 层面会继续朝更适合多人长时间游玩的形式优化，比如头像化、信息分组、交互提示和更明确的状态反馈。
- 如果同步质量足够稳定，未来也可以逐步加入更多轻量摘要信息，例如某个选择的候选项、阶段性意图、或更适合围观和讨论的精简视图。
- 长期来看，`PartyObserver` 希望变成一个“协作感知层”：你不需要主动询问队友“你那边现在是什么情况”，而是能直接从界面知道他此刻的决策上下文。

## 📊 DamageMeter

`DamageMeter` 的定位并不只是显示一个输出排行榜，而是尽量把一场战斗里真正值得复盘的数据组织成可读、可比较、可累计的面板。

在联机环境里，很多信息如果只看最终谁打了多少伤害，其实会丢掉大量过程细节。  
谁提供了更多团队增益？谁承担了更多承伤？哪一回合打出了峰值？哪名角色经常浪费能量？哪场战斗的效率异常高或异常低？  
`DamageMeter` 想做的，是把这些过程型数据也纳入同一个可视化框架里。

### 功能描述

- 在战斗期间提供可持续查看的统计面板，用于观察当前战斗和累计数据。
- 已支持多种统计维度，包括总输出、真实伤害、承伤、每回合输出、团队增伤贡献、团队格挡支援、出牌量、格挡、能量、伤害效率、溢出伤害、药水使用、减益施加等。
- 除了简单总量，还提供与节奏有关的图表能力，适合观察队伍输出曲线、回合峰值和资源浪费趋势。
- 支持战斗记录、死亡记录、卡牌流转等更偏复盘性质的维度，使它不只是“打完看排名”，而是能回头分析战斗过程。
- 提供长期记录能力，例如最高单次输出、单场最高总伤、最佳回合输出、最多出牌数、单场最高格挡和累计战斗数据等。
- 支持面板位置、缩放、透明度、显示行数等设置，适合根据自己的屏幕布局进行调整。
- 从实际用途上看，它既适合多人房间里做战斗后复盘，也适合单人环境里观察构筑表现、判断资源使用是否合理、确认某些套路到底有没有达到预期。

### 版本展望

`DamageMeter` 后续的重点，会从“已经能看很多数据”继续走向“让这些数据更有解释力、更容易比较、也更适合长期积累”。

- 近阶段会继续打磨现有分类面板的可读性，包括图表表达、行数控制、重点数据突出和不同战斗节奏下的显示稳定性。
- 后续很适合加入更细的归因层，例如把伤害、格挡或资源收益进一步拆到卡牌、遗物、能力、回合窗口等粒度，帮助判断构筑里真正起作用的是哪一部分。
- 另一个明确方向，是把“当前战斗统计”扩展成“整局流程复盘”，例如按房间、按精英、按 Boss、按角色甚至按 run 维度进行对比。
- 如果后续版本继续深化图表能力，`DamageMeter` 也很适合加入更完整的趋势视图，让玩家更容易看出输出爬升点、资源断档点和爆发回合。
- 长期来看，它可以从局内 HUD 继续成长为更完整的分析工具：不仅告诉你“结果是什么”，还尽量回答“为什么会是这个结果”。

## 🛠️ 本地构建说明

- 当前项目文件默认假设仓库位于游戏安装目录下的 `modding/` 目录中。
- `build-combatquill.ps1` 用于构建或发布 `CombatQuill`。
- `build-partyobserver.ps1` 用于构建或发布 `PartyObserver`。
- `DamageMeter/build.ps1` 用于构建 `DamageMeter`，并可选择直接安装到本地 `mods/` 目录。
- `CombatQuill` 和 `PartyObserver` 当前使用仓库内的本地工具链进行构建；`DamageMeter` 使用系统可用的 `dotnet` 进行编译。

## 🚧 当前状态

这三个 mod 都已经具备继续公开迭代的基础，但整体仍然是早期版本。  
如果你正在关注这个仓库，最值得期待的并不是某一个“单点功能”上线，而是这三个方向逐渐拼成一个更完整的联机辅助体验：

- 更自然的局内标注
- 更清晰的队友状态观察
- 更完整的战斗和构筑复盘

这也是这个仓库后续会持续推进的主线。
